# Smart Laundry

เว็บไซต์จัดการร้านซักผ้าหยอดเหรียญ/บริการซักผ้า ให้ลูกค้าตรวจสอบสถานะเครื่อง เลือกโปรแกรมและจองเครื่อง ชำระเงินผ่าน PromptPay และติดตามรายการซักได้ ส่วนผู้ดูแลสามารถจัดการเครื่อง บริการ ผู้ใช้ และตรวจสอบรายการชำระเงินได้

## ฟีเจอร์หลัก

### สำหรับผู้ใช้

- สมัครสมาชิก เข้าสู่ระบบ แก้ไขโปรไฟล์ และเปลี่ยนรหัสผ่าน
- ดูเครื่องซักผ้า และสถานะว่าง/กำลังใช้งาน/ปรับปรุง
- จองเครื่อง เลือกโปรแกรมซัก และเพิ่มบริการอบแห้งหรือน้ำยาปรับผ้านุ่ม
- ชำระเงินด้วย QR PromptPay พร้อมส่งสลิปเพื่อตรวจสอบผ่าน SlipOK
- ดูประวัติการใช้งานและสถานะการซัก
- เชื่อมบัญชี LINE เพื่อรับการแจ้งเตือน และรีเซ็ตรหัสผ่านด้วย OTP ทางอีเมล
- ส่งรายงานปัญหาเกี่ยวกับเครื่องหรือบริการ โดยระบบสามารถแจ้งผู้ดูแลผ่าน LINE ได้เมื่อกำหนดค่าไว้

### สำหรับผู้ดูแล

- ดูแดชบอร์ด ยอดขาย และสถิติการใช้งาน
- เพิ่ม แก้ไข ปิดใช้งาน หรือลบเครื่อง และปรับราคา/เวลาให้บริการ
- ตรวจสอบประวัติธุรกรรมและจัดการสถานะสมาชิก
- ตั้งค่าการแจ้งเตือน LINE และดูรายงานปัญหา

## เทคโนโลยี

- **Backend:** Python, Flask
- **Frontend:** HTML, CSS, JavaScript
- **ฐานข้อมูล:** SQLite
- **บริการภายนอก (ตั้งค่าเพิ่มเติม):** SlipOK, PromptPay, LINE Messaging API และ Gmail SMTP

## เริ่มต้นใช้งาน

ต้องติดตั้ง Python 3.10 ขึ้นไปก่อน

```bash
# 1. สร้างและเปิดใช้งาน virtual environment
python -m venv .venv
source .venv/bin/activate          # macOS / Linux
# .venv\Scripts\activate           # Windows PowerShell

# 2. ติดตั้ง dependencies
python -m pip install -r requirements.txt

# 3. เริ่มเว็บเซิร์ฟเวอร์สำหรับพัฒนา
python app.py
```

เปิดเว็บที่ <http://127.0.0.1:5000/> ฐานข้อมูล `smartlaundry.db` และตารางที่จำเป็นจะถูกสร้างขึ้นโดยอัตโนมัติเมื่อเริ่มแอปครั้งแรก

## บัญชีเริ่มต้น

เมื่อฐานข้อมูลยังไม่มีบัญชี ระบบจะสร้างบัญชีเริ่มต้นดังนี้:

| ประเภท | อีเมล | รหัสผ่าน |
|---|---|---|
| ผู้ดูแล | `admin@smartlaundry.local` | `admin1234` |
| ผู้ใช้ทดสอบ | `user@test.com` | `user1234` |

เปลี่ยนรหัสผ่านและตั้งค่าความปลอดภัยก่อนนำระบบขึ้นใช้งานจริง บัญชีผู้ดูแลจะสร้างจาก `ADMIN_EMAIL` และ `ADMIN_PASSWORD` เฉพาะตอนที่ยังไม่มีบัญชีผู้ดูแลในฐานข้อมูล

## วิธีใช้งานโดยย่อ

1. สมัครสมาชิกและเข้าสู่ระบบ
2. ตรวจสอบเครื่องที่ว่าง เลือกโปรแกรมซัก และเลือกบริการเสริม (ถ้าต้องการ)
3. ยืนยันการจอง แล้วชำระเงินด้วย QR PromptPay ภายในเวลาที่กำหนด
4. เมื่อยืนยันการชำระเงินแล้ว ระบบจะเริ่มรอบซักและแสดงสถานะ/เวลาโดยประมาณ
5. ตรวจสอบรายการย้อนหลังได้จากหน้า History; ผู้ดูแลเข้าหน้าจัดการได้หลังเข้าสู่ระบบด้วยบัญชีผู้ดูแล

ค่าเริ่มต้นสำหรับการพัฒนาคือเครื่องซัก 6 เครื่อง ขนาด 10 กก. โปรแกรมซักด่วน/มาตรฐาน/สะอาดพิเศษราคา 40/50/60 บาท และบริการอบแห้ง/ปรับผ้านุ่มราคา 20/10 บาท ตามลำดับ ราคาสามารถเปลี่ยนได้จากหน้าจัดการของผู้ดูแล

## ตั้งค่าการเชื่อมต่อเสริม

สร้างไฟล์ `.env` ที่ root ของโปรเจกต์ แล้วกำหนดค่าที่ต้องการใช้งาน ตัวอย่าง:

```dotenv
SECRET_KEY=replace-with-a-long-random-secret
ADMIN_EMAIL=admin@example.com
ADMIN_PASSWORD=replace-with-a-strong-password
DEMO_MODE=0
PROMPTPAY_ID=your-promptpay-number-or-id

# ตรวจสอบสลิป
SLIPOK_API_KEY=
# SLIPOK_URL=https://api.slipok.com/api/line/apikey

# ส่งอีเมล OTP สำหรับรีเซ็ตรหัสผ่าน
GMAIL_USER=
GMAIL_APP_PASS=

# แจ้งเตือนผ่าน LINE
LINE_CHANNEL_ACCESS_TOKEN=
LINE_ADMIN_USER_ID=
```

- `DEMO_MODE=1` เปิดปุ่มจำลองการชำระเงินสำเร็จสำหรับทดสอบ; ควรตั้งเป็น `0` ในระบบจริง
- การตรวจสอบสลิปต้องมี `SLIPOK_API_KEY` และการสร้าง QR ใช้ `PROMPTPAY_ID`
- การส่งอีเมลต้องตั้งค่า Gmail SMTP ให้พร้อมใช้งาน
- การแจ้งเตือน LINE ต้องมี Channel Access Token; การแจ้งเตือนผู้ดูแลต้องตั้ง `LINE_ADMIN_USER_ID` และตั้งค่า token/เปิดใช้งานจากหน้าผู้ดูแลด้วย
- เก็บ `.env` และ secret ทั้งหมดไว้นอก Git ห้ามใช้ค่าทดสอบหรือรหัสผ่านเริ่มต้นใน production

## ข้อมูลตัวอย่าง

หากต้องการข้อมูลสมาชิก ประวัติการซัก และรายการธุรกรรมตัวอย่าง:

```bash

บัญชีตัวอย่างใช้รหัสผ่าน `demo1234` ส่วนการล้างข้อมูลตัวอย่างเดิมแล้วสร้างใหม่ ใช้:

```

## API และการเชื่อมต่อ ESP32

แอปมี JSON API ที่หน้าเว็บใช้ภายใน โดย endpoint หลักมีดังนี้:

| Method | Endpoint | การใช้งาน / สิทธิ์ |
|---|---|---|
| `GET` | `/api/machines/status` | ดูสถานะเครื่อง |
| `POST` | `/api/bookings` | สร้างรายการจอง (ต้องเข้าสู่ระบบ) |
| `GET` | `/api/bookings/pending` | ดูรายการจองที่รอชำระ (ต้องเข้าสู่ระบบ) |
| `POST` | `/api/payment/start` | เริ่มชำระเงินและสร้างข้อมูล QR (ต้องเข้าสู่ระบบ) |
| `POST` | `/api/payment/upload-slip` | ส่งสลิปตรวจสอบ (ต้องเข้าสู่ระบบและตั้งค่า SlipOK) |
| `GET` | `/api/payment/<payment_id>/status` | ตรวจสอบสถานะชำระเงินของตนเอง (ต้องเข้าสู่ระบบ) |
| `POST` | `/api/payment/cancel` | ยกเลิกรายการจองที่รอชำระ (ต้องเข้าสู่ระบบ) |
| `POST` | `/api/payment/<payment_id>/simulate-success` | จำลองจ่ายสำเร็จ (ต้องเข้าสู่ระบบและ `DEMO_MODE=1`) |
| `GET` | `/api/user/history` | ดูประวัติของผู้ใช้ปัจจุบัน (ต้องเข้าสู่ระบบ) |
| `GET` | `/api/esp32/status/<machine_code>` | ให้ ESP32 อ่านสถานะเครื่องและเวลาที่เหลือ |
| `POST` | `/api/esp32/complete` | ให้ ESP32 แจ้งเมื่อรอบซักเสร็จ โดยส่ง `machine_code` ใน JSON |

เมื่อ `DEMO_MODE=1` จะเปิด endpoint จำลองการชำระเงินสำหรับทดสอบด้วย; ปิดโหมดนี้และตั้งค่าการยืนยันสลิปก่อนใช้งานจริง endpoint สำหรับ ESP32 ยังไม่มีการยืนยันตัวตนอุปกรณ์ในแอป ควรจำกัดการเข้าถึงผ่านเครือข่ายหรือ gateway ที่เชื่อถือได้ก่อนเชื่อมต่อเครื่องจริง

## การนำขึ้นใช้งาน

สำหรับ production ให้ใช้ WSGI server แทน development server ของ Flask ตัวอย่าง:

```bash
gunicorn --bind 0.0.0.0:8000 app:app
```

กำหนด environment variables ให้ครบ ใช้ HTTPS และตรวจสอบให้แน่ใจว่าที่เก็บ `smartlaundry.db` มี persistence เพราะข้อมูลสมาชิกและธุรกรรมเก็บอยู่ใน SQLite ในเครื่อง นอกจากนี้ workflow ใน GitHub Actions จะทำงานเมื่อมีการ push ไปยัง branch `main`

### ข้อควรทราบสำหรับ production

- กำหนด `SECRET_KEY`, รหัสผ่านผู้ดูแล และค่าบริการภายนอกผ่าน environment variables ที่ปลอดภัย ห้ามใช้บัญชีเริ่มต้นหรือ `DEMO_MODE=1`
- SQLite เป็นไฟล์ในเครื่อง ไม่เหมาะกับหลาย instance ที่ไม่มี shared persistent storage; สำรองไฟล์ฐานข้อมูลและทดสอบการกู้คืนเป็นประจำ
- รหัส OTP และข้อมูลชั่วคราวบางส่วนเก็บในหน่วยความจำของ process จึงอาจหายเมื่อแอป restart และไม่เหมาะกับการรันหลาย worker โดยไม่มีการปรับระบบจัดเก็บร่วมกัน
- การตั้งค่าเวลาเปิด/ปิดร้านในหน้าผู้ดูแลยังไม่บังคับเวลาจองในโค้ดปัจจุบัน (ระบบเปิดรับจองตลอดเวลา)
